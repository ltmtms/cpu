02

Opcode and operand

Every machine-code instruction is a pattern of bits. In our CPU an instruction is one 8-bit word: the first 4 bits say what to do, the last 4 bits say what to do it to.

High-level code
x = x + 1
Assembly (after compiling)
LOAD  6   ; ACC ← x
ADD   7   ; ACC ← ACC + 1
STORE 6   ; x ← ACC
HALT
Machine code in RAM
0001 0110   addr 0
0010 0111   addr 1
0011 0110   addr 2
0000 0000   addr 3

One line of high-level code became four instructions. The variable x sits at address 6, and the constant 1 sits at address 7, because ADD here expects an address as its operand.

What the CU will do

Where the parts go

Opcode (operation code): tells the Control Unit which operation to carry out. With 4 bits there are 24 = 16 possible opcodes, so this CPU's instruction set can have at most 16 instructions.

Operand: the data the operation works on. Usually it is an address in memory (direct addressing), so 4 bits can reach 16 addresses. With immediate addressing the operand is the value, so ADDI 1 could do x + 1 without reading address 7.

Real CPUs use longer instructions (16, 32 or 64 bits) so they get more opcodes and can address far more memory, but the split is the same idea.

03

What “ADD” looks like inside the ALU

When the CU decodes ADD 7, it tells the ALU to add. The ALU has no idea what “5” or “1” means. It only sees voltages on wires, high (1) or low (0), and pushes them through logic gates.

A full adder adds one column

Adding binary works like column addition at school: add the two digits plus any carry from the column to the right, write down a sum bit, and pass a carry to the left. A full adder does exactly that for one column with five gates. The two dashed boxes are half adders (one XOR and one AND each); an OR gate merges their carries. Click A, B and Cin to change the inputs.

Eight full adders make an 8-bit adder

Chain eight full adders so each carry-out feeds the next column's carry-in, and you have a ripple-carry adder: the circuit inside the ALU that executed ACC ← ACC + MDR in the lab. It is preloaded with that exact sum, 5 + 1. Press Run the adder to watch the carry ripple from bit 0 leftwards. Click any A or B bit to change the numbers.

04

Why we need two's complement

The adder only understands patterns of bits. To store negative numbers we must choose a pattern for them, and the choice decides whether that same adder still gives the right answer.

Attempt 1: sign and magnitude

The obvious idea is to use the leftmost bit as a sign (0 = +, 1 = −) and the rest as the size. So +3 is 0011 and −3 is 1011. It is easy for people to read, but feed it to the adder and things go wrong. Move the sliders and compare.

3
-3

Sign and magnitude has two problems:

1. Two zeros. 0000 is +0 and 1000 is −0. Comparisons need extra logic, and one pattern is wasted.

2. The plain adder gives wrong answers whenever the signs differ. The CPU would need a separate subtractor, plus logic to compare sizes and pick the sign.

Two's complement: the leftmost bit is worth a negative amount

In two's complement the most significant bit keeps its place value but becomes negative. In 8 bits it is worth −128 instead of +128. Everything else is ordinary binary. Click the bits in the top row.

To negate a number, invert every bit and add 1. The lower rows do that live to the number you set.

Why it works: the number wheel

A 4-bit adder throws away any carry out of the leftmost bit, so it counts round a wheel of 16 patterns: after 1111 comes 0000. Adding B means moving B steps clockwise.

Two's complement simply labels the left half of the wheel with negative numbers. Then −3 (1101, which the adder sees as 13) moves 13 steps clockwise, which lands exactly where 3 steps anticlockwise would. Subtraction comes free from addition.

So why do CPUs use it?

One adder does everything

A − B is worked out as A + (NOT B) + 1. The ALU flips B with XOR gates and sets the first carry-in to 1. Try the SUB button on the 8-bit adder above.

Only one zero

00000000 is the only zero, so every one of the 256 patterns is a different number: −128 to +127.

No sign logic

The adder never looks at signs. Positive plus negative, negative plus negative: the same gates, the same answer.

Overflow is easy to spot

If the carry into the sign bit differs from the carry out of it, the true answer did not fit. One XOR gate sets the overflow flag.

05

Check yourself

Answer in your head, then open each card.

Why does the PC get incremented during the fetch, not after the execute?

So it already points at the next instruction. If the current instruction is a JUMP, the execute phase simply overwrites the PC with the jump address.

Which registers connect directly to the buses?

The MAR drives the address bus (one-way, CPU to memory). The MDR is connected to the data bus (two-way). The CU drives the control bus (read, write, clock signals).

In 0010 0111, what is the opcode and what is the operand?

Opcode 0010 = ADD. Operand 0111 = 7, the address of the value to add.

How many memory reads does running x = x + 1 take in total?

Six: four instruction fetches (LOAD, ADD, STORE, HALT) plus two data reads (x and the constant 1). There is also one memory write for STORE.

Work out −6 in 8-bit two's complement.

+6 = 00000110. Invert: 11111001. Add 1: 11111010. Check: −128 + 64 + 32 + 16 + 8 + 2 = −6.

Why does 100 + 50 give −106 in 8-bit two's complement?

150 is larger than +127, the biggest 8-bit two's complement number. The carry into the sign bit is 1 but the carry out is 0, so the overflow flag is set and the result has wrapped round the wheel.
